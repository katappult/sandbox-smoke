# Katappult Project Setup

Skill to bootstrap a Katappult project after archetype generation. The entity models are already generated — this skill sets up the development environment and verifies everything works.

---

## When to use

Use this skill when:
- A new project has just been generated by the Katappult MCP (archetype)
- The project compiles but has never been run
- The H2 local database needs to be initialized for the first time

Do **not** use when adding features to an existing project (use `/senior-backend-dev` or `/senior-frontend-dev`).

---

## Step 1 — Verify project structure

Check that the generated structure is present:

```
src/
  main/java/{basePackage}/
    generated/          ← generated vertical slices (do not touch)
  resources/
    changelogs/         ← Liquibase changelogs
frontend/
  pages/
  components/
  services/
pom.xml
CLAUDE.md
```

If `CLAUDE.md` is missing or project-specific fields are still placeholders (`{projectName}`, `{basePackage}`), update them now.

---

## Step 2 — Configure CLAUDE.md

If this is a fresh project without a `CLAUDE.md`, copy the template from the reference project and fill in:

| Placeholder | Value |
|---|---|
| `{Entity}` | The main entity name of this project |
| `{basePackage}` | Java base package (e.g. `com.company.myproject`) |
| Languages supported by i18n | Update the language list |

---

## Step 3 — First backend build + DB init

```bash
mvn clean install -PdropDb,updateDb -DskipTests
```

This:
- Compiles all Java sources
- Drops and recreates the H2 schema (`PdropDb`)
- Runs all Liquibase changelogs (`updateDb`)
- Skips tests for speed

Expected: `BUILD SUCCESS`

If the build fails:
- Check Java version: `java -version` → must be 21
- Check Maven version: `mvn -version` → must be 3.x
- Check pom.xml parent version matches the Katappult platform version

---

## Step 4 — Start the backend

```bash
mvn spring-boot:run
```

Wait for: `Started ... in X seconds`

Verify: `curl -s http://localhost:8080/actuator/health` → `{"status":"UP"}`

---

## Step 5 — Frontend setup

```bash
cd frontend
npm install
```

Create `frontend/.env.local` if absent:
```
NEXT_PUBLIC_BACKEND_URL=http://localhost:8080
```

Start the dev server:
```bash
npm run dev
```

Wait for: `✓ Ready on http://localhost:3000`

---

## Step 6 — Run integration tests (smoke check)

```bash
mvn clean verify
```

All generated tests should pass. If a test fails, it indicates a misconfiguration in the Liquibase changelogs or entity mapping — investigate before proceeding.

---

## Step 7 — Initial commit

```bash
git add .
git commit -m "feat: initialize project from Katappult archetype"
```

Follow the `/commit` command conventions (conventional commits + emoji) for subsequent commits.

---

## Step 8 — Create develop branch (Git Flow)

```bash
git checkout -b develop
git push -u origin develop
```

All feature work branches from `develop`.

---

## Post-setup checklist

- [ ] `mvn spring-boot:run` starts without errors
- [ ] `npm run dev` serves on port 3000
- [ ] `mvn clean verify` — all tests pass
- [ ] `CLAUDE.md` placeholders replaced with real project values
- [ ] `develop` branch created and pushed
- [ ] `.env.local` present (gitignored)
